# B2.5 gameplan — Comic editor in React (broken into ≤125k-context steps)

> **What this is.** B2.5 from `progress.md` is the **comic editor in the React admin**
> (`admin-frontend/`). It is the first of the three content editors (B2.5 comic / B2.6 story /
> B2.7 media) and the **complete comic‑editor spec** (the old B3 row was merged into it).
> This file splits it into **small, independently‑verified steps** so that **no single session
> turn ever needs more than ~125k tokens of context** to finish and hand off cleanly.
>
> **The spec (verbatim from `progress.md`, §4, B2.5 row):**
> Split view: **editor (left) + live preview (right)**. Drag/drop a batch of images;
> **click the dropzone to paste**; **double‑click opens the file explorer**; **drag pages to
> reorder** (PATCH `comic_pages.page_number`; reorder doubles as planning); **caption field
> above each page** (`comic_pages.caption`; shows above the image when the comic displays);
> **auto‑save** (debounced PATCH on every change — no "post" step). Uses B2.4's upload +
> content endpoints. **Verify:** upload 3 pages, reorder, caption, hard reload → state
> survives from the DB. One focused component — **no marquee yet (that's B4).**
>
> **How to use (handoff protocol — same spirit as §7 in `progress.md`):**
> 1. Start at the first step marked `⬜`.
> 2. Do **only that step.** Touch only the files it lists. Read only the anchors it names.
> 3. When it's green, flip its **Status** to `✅` and fill in **Done / gotchas** (what we
>    built, what a future session must NOT re‑troubleshoot).
> 4. **The last step (Step 6) updates `progress.md`.** Do not mark B2.5 done in
>    `progress.md` before Steps 1–5 are all `✅`.
>
> **The 125k rule (why the steps are cut this way):**
> - **Never `read` all of `server.js`** (~1,760 lines / ~85 KB and only grows). B2.5 is
>   **frontend‑only** — you should almost never need it. Use the endpoint table in the
>   cheat‑sheet (pinned below) instead of opening the file. If a server bug does surface,
>   `grep` the marker + `read` a bounded window (offset + limit ≤ ~150 lines).
> - **One feature per step** (shell → dropzone/upload → reorder → captions), so the
>   read‑anchors + write‑component + test + debug cycle stays small. Each step builds on the
>   previous one's green component — you never re‑read a huge file to "remember" state.
> - **Every step ends green** (its own quick verify). A handoff never leaves a broken build.
> - **Don't re‑discover house patterns** — they're pinned in the cheat‑sheet below.
> - **Keep it dependency‑free.** No `dnd‑kit`, no `react‑beautiful‑dnd`, no `file‑picker`
>   package. Use native HTML5 drag‑and‑drop, the Clipboard API, and a hidden
>   `<input type="file">`. (Adding a dep = a new install to reason about + a sandbox
>   `npm install` to babysit.)

## House‑pattern cheat‑sheet (READ THIS ONCE, don't re‑discover it)

**Repo:** `gqsa-Site` (this workspace). Node + Express 4 + `node:sqlite` backend; `/admin`
is the **React + Vite SPA** in `admin-frontend/` (B2.2). Public site stays EJS. B2.5 adds
**one component** (`ComicEditor.jsx`) mounted inside the existing `App.jsx` shell.

**Run it (dev = two terminals, from the repo root):**
```
npm run dev                      # Express on :3000
npm run dev -w admin-frontend    # Vite on :5173 (proxies /api + auth routes to :3000)
```
Log in **on `:5173`** (open `http://localhost:5173/login`, log in with the admin account),
then open `http://localhost:5173/admin/`. The session cookie is same‑origin, so every
`fetch('/api/admin/…')` from the SPA just works — **no CORS, no cookie juggling**
(`vite.config.js` `server.proxy` handles it). Prod/Render is one process: Express serves
the built `admin-frontend/dist` at `/admin` (`npm run build:admin`).

**The shell already owns the CSRF token — don't re‑fetch it.** `App.jsx` boots with
`GET /api/admin/boot` → `{ isAdmin, csrfToken, emailTransport }`, and the "ok" branch
passes `csrfToken` **as a prop** to whatever it renders (it does this for `<Tracker>`).
`ComicEditor` takes `csrfToken` the same way: `function ComicEditor({ csrfToken })`.

**The fetch house pattern (copy from `Tracker.jsx` — it is the template for every
state‑changing call this app makes):**
```js
const res = await fetch('/api/admin/…', {
  method: 'POST',                                   // or PATCH
  headers: { 'Content-Type': 'application/json', 'X-CSRF-Token': csrfToken },
  body: JSON.stringify({ … }),
})
if (!res.ok) {
  const data = await res.json().catch(() => ({}))
  throw new Error(data.error || `answered ${res.status}`)   // the server's own message
}
```
- **JSON POST/PATCH** → send `Content-Type: application/json` + the `X-CSRF-Token` header.
- **GET routes are CSRF‑exempt** (the server middleware checks POST‑only), so
  `GET /api/admin/content` needs no token.
- **multipart uploads** → do **NOT** set `Content-Type` (the browser sets the
  multipart boundary). Send the `X‑CSRF‑Token` header only. See the upload block below.

**Optimistic‑update house pattern (also from `Tracker.jsx`):** flip the local state
instantly → fire the request → on failure **roll the state back** and show the error line.
Use it for reorder (Step 3) and captions (Step 4).

**The B2.4 endpoint contract (code against EXACTLY these — pinned, don't re‑derive):**
| Method + path | Body | Returns | Notes |
|---|---|---|---|
| `GET /api/admin/content` | – | `{stories, comics, pages, images, videos, counts:{…}}` | **the editor's data source.** The key for comic pages is **`pages`** (not `comic_pages`). Each page row: `{id, comic_id, page_number, file_path, caption}`. Each comic: `{id, title, description, publish_date, is_member, tier_id, created_at, updated_at}`. |
| `POST /api/admin/upload` | multipart: **`kind` FIRST, then `file`** | `{success, file_path, originalName, bytes}` | `file_path` is URL‑style (`/uploads/comics/<uuid>/<name>`) and `GET`‑able via the existing `express.static('public')`. 100 MB cap → 400. |
| `POST /api/admin/comics` | `{title, description?, publish_date?, is_member?, tier_id?}` | `201 {success, id}` | **`title` required** → 400 otherwise. |
| `DELETE /api/admin/comics/:id` | – | `{success}` | 404 if missing; **its pages cascade** (node:sqlite runs with `foreign_keys` ON). |
| `POST /api/admin/comic-pages` | `{comic_id, page_number, file_path, caption?}` | `201 {success, id}` | `page_number` integer ≥ 1; 404 if comic missing; **409** if the number is taken. |
| `PATCH /api/admin/comic-pages/:id` | `{page_number?, caption?, file_path?}` | `{success, id}` | Partial: absent field keeps the current value; **explicit `null` CLEARS `caption`** (a blank `''` would store an empty string — map blank → `null`). 409 on a `page_number` collision. |
| `PATCH /api/admin/comics/:id/reorder` | `{page_ids: [idA, idB, …]}` | `{success, comic_id, order}` | **CONTRACT: `page_ids` must be EXACTLY the comic's current full page set, in the new order.** A partial or duplicate list → 400 (never a silent patch). Server does a two‑phase renumber internally — you just send the ordered ids. |
| `DELETE /api/admin/comic-pages/:id` | – | `{success}` | 404 if missing. |

**The multipart upload block (the ONE place field order matters):**
```js
async function uploadImage(file, csrfToken) {
  const fd = new FormData()
  fd.append('kind', 'comics')      // MUST come BEFORE the file (multer reads req.body.kind
  fd.append('file', file)          // in destination() while walking the stream in order)
  const res = await fetch('/api/admin/upload', {
    method: 'POST',
    headers: { 'X-CSRF-Token': csrfToken },   // NO Content-Type — browser sets the boundary
  })
  if (!res.ok) { const d = await res.json().catch(() => ({})); throw new Error(d.error || `upload ${res.status}`) }
  return res.json()                 // → { success, file_path, … }
}
```

### Step 2 — Dropzone: drag/drop + click‑to‑paste + double‑click file picker → upload → insert pages  ⬜
**Goal:** the three image‑input paths (drag a batch / click to paste / double‑click to open
the file explorer) each land new pages in the selected comic, via B2.4's `upload` +
`comic-pages` endpoints.

**Touch:** `ComicEditor.jsx` (the dropzone + the upload pipeline), `index.css` (dropzone
styling).

**Do:**
1. A dropzone element at the top of the left pane. Wire **three** distinct actions — and
   **disambiguate single‑click vs double‑click** (a double‑click also fires two `click`
   events, so a naive `onClick=paste` + `onDoubleClick=picker` would paste *and* open the
   picker):
   ```js
   const clickTimer = useRef(null)
   const onZoneClick = () => {
     if (clickTimer.current) return                      // a double‑click is in flight
     clickTimer.current = setTimeout(() => { clickTimer.current = null; doPaste() }, 250)
   }
   const onZoneDoubleClick = () => {
     clearTimeout(clickTimer.current); clickTimer.current = null
     fileInputRef.current?.click()                        // hidden <input type="file">
   }
   ```
   - **drag/drop:** `onDragOver` → `e.preventDefault()` (+ highlight); `onDrop` →
     `e.preventDefault()`, `e.dataTransfer.files` → filter `type.startsWith('image/')` →
     `addFiles([...])`.
   - **click → paste:** `doPaste()` → `navigator.clipboard.read()` → for each item,
     find an `image/*` type (`Array.from(item.types).find(t => t.startsWith('image/'))`) →
     `await item.getType(type)` → a `File` → `addFiles([file])`. Wrap in try/catch:
     permission‑denied or no image → a friendly muted message, no crash.
   - **double‑click → picker:** a hidden `<input ref={fileInputRef} type="file"
     accept="image/*" multiple hidden onChange={e => { addFiles([...e.target.files]); e.target.value = '' }} />`.
2. The **upload pipeline** (`addFiles(files)`), **sequential** (the server's multer is
   single‑file): for each file, in order —
   1. `uploadImage(file, csrfToken)` (the block in the cheat‑sheet) → `{ file_path }`.
   2. `page_number = (max page_number among this comic's current pages) + 1`.
   3. `POST /api/admin/comic-pages` `{ comic_id: selectedId, page_number, file_path }`
      (JSON + `X-CSRF-Token`) → `201 {id}`.
   4. Append the new row `{ id, comic_id, page_number, file_path, caption: null }` to the
      local `pages` state (so the list + preview update immediately).
   - A busy indicator: "Uploading i/N…" while the pipeline runs; an error line if any step
     fails (and stop — don't insert a half‑uploaded set).

**Verify (green = done):** select a comic (or make a new one). (a) **Drag** 3 test images
